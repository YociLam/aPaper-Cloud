# E1 journal extension (unreleased)

Schema 1 keeps `venues` exclusively conferences. A separate optional `journals` array contains journal sources using the same bounded pack reference and annual selection ID format. Legacy clients ignore that array and cannot select its collections. New clients explicitly validate `source_kind: journal`, journal identity and collection coverage before merging into their one public catalog. Unknown kinds and misplaced journals are rejected. Existing conference bytes and IDs remain unchanged.

Internal `venue_id`/`edition_id` remain transport compatibility aliases for source/annual collection, not a claim about publisher volumes. A `journal` object retains canonical title, ISSNs, publisher, native article type, actual volume/issue/article number, online/issue dates and license URL. Runtime `source: journal` and citation fields survive normalization. DOI is canonical paper identity; issue assignment does not change it. Collection coverage records cutoff, declared types and identity accounting. Annual partition is not a publisher volume.

One downloader, verified cache, 100000-record budget, Core retrieval and canonical selected-ID set remain owners. Candidate version is 0.16 (preceding local 0.15 unreleased; public HTTPS version verified 0.14 on 2026-10-14). This is not a public release.

Frozen acquisition cutoff: **2026-10-14T15:44:19Z**. Source rule: publisher online publication date where supplied, otherwise publisher issued date; preserve issue date separately. Crossref deposit/index times are never publication dates. Enumerate current-year publisher-deposited identities with terminal cursor checks, quarantine updates/corrections/retractions and absent licensed abstracts, declare unresolved rights/acquisition separately. No future-year backfill.

The same safe split is retained in the public FFI JSON (`venues` conferences, `journals` journals). New Rust and Swift validate section/kind agreement and then use one combined in-memory catalog. Encoding splits that canonical view again. Thus both an old downloader and an old Swift catalog decoder exclude journals instead of ignoring a kind flag inside legacy conference rows. This is not a second catalog owner or another navigation level. Pre-E1 clients reject unsupported journal paper enums in a shared newer DailyPaper store; no production-root downgrade or migration is claimed.

Rights scope is effective CC BY / CC0 abstracts. Explicit NC/ND exclusions are not upstream unavailability. DOI-linked corrections/updates and supplied relations remain in reconciliation receipts; admitted publisher new-version links remain in normalized metadata. Known failed PDF URLs are cleared without discarding otherwise admissible journal metadata. Such records have no Open/Import action, while the existing conference PDF admission rule is retained.
